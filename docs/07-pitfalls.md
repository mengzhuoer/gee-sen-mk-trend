# 07 · 踩坑复盘：从 NDVI 教程到 GPP 山西案例

记录复刻过程中真实遇到、会反复出现的问题。每条按“现象 → 根因 → 解决 → 教训”组织。

---

## A. 方法与口径

### A1. 年度指标照搬“取最大”，GPP 结论会错

- **现象**：把 NDVI 的 `max()` 直接套到 GPP，年际曲线变平，趋势偏弱。
- **根因**：NDVI 是状态量，取生长季峰值合理；GPP 是通量，只有累加才有物理意义。
- **解决**：GPP 改为全年 46 个 8 天时段累加；每年时段不全的像元整年作废。
- **教训**：换变量先问“它是状态量还是通量”，再决定年度合成方式。

### A2. 数据集结论以实跑 `print` 为准

- **现象**：在 `MOD17A3HGF`（年产品）与 `MOD17A2HGF`（8 天产品）之间反复，
  过程中还出现过“年产品没有 Gpp 波段”的错误说法。
- **根因**：依赖记忆/二手描述，而不是 catalog 与实跑输出。
- **解决**：在 Code Editor 打印 `bandNames`、影像数、每年时段数；
  最终确认 `MOD17A2HGF` 波段为 `["Gpp","PsnNet","Psn_QC"]`，2001—2021 共 966 张，
  每年 46 期。
- **教训**：数据集的波段、比例因子、时间步长，一律以实际 `print` 为准。

### A3. 比例因子有两级，容易差 10 倍

- **现象**：GPP 数值量级不对。
- **根因**：8 天 Gpp 原始整数 × 0.0001 = kg C/m²/时段；
  全年累加后再 × 0.1 = g C/m²/year。
- **解决**：本地全程用整数运算，只在输出时乘 0.1；CSV 与图都标注单位。
- **教训**：把“原始值 → 物理值”的换算链写进 README，不要只留在脑子里。

### A4. “基本稳定”在连续变量上几乎为空

- **现象**：五级图看起来像四级图，稳定类只有 4.7 km²。
- **根因**：判据是“斜率精确等于 0”，连续变量的斜率几乎不会精确为 0。
- **解决**：在文档中说明这是预期行为；如需非零稳定区，显式设置容差阈值。
- **教训**：分类阈值要服务于科学问题，不能为了图好看事后调整。

## B. 边界与资产

### B1. GAUL 省名不是拼音（最典型的一次连锁故障）

- **现象**：`研究区要素数 = 0`，`roi.bounds() = null`，随后几十行
  `Image.select: Parameter 'input' is required and may not be null`。
- **根因**：用 `ADM1_NAME == 'Shanxi'` 精确匹配，GAUL 实际值是 `Shanxi Sheng`；
  空集合 → `filterBounds` 得到 0 张影像 → `first()` 为 null → 全链条崩溃。
- **解决**：改用太原坐标 `[112.549, 37.871]` 空间选省，并打印实际名称核对。
- **教训**：行政区名称匹配必须打印真实值；能用空间选就不用名称匹配。

### B2. 上传资产名与脚本里的路径不一致

- **现象**：`Collection asset 'projects/xxx/assets/shanxi' not found`。
- **根因**：上传后的资产名与预设路径不同。
- **解决**：脚本里加 `ee.data.listAssets` 自动解析，失败回退 GAUL；
  最终先用 GAUL 跑通，边界做成一个开关。
- **教训**：资产 ID 不要靠猜，先列出再引用。

### B3. Shanxi（晋）与 Shaanxi（陕）

- **风险**：拼音只差一个字母，名称匹配极易选错省。
- **解决**：全程用太原点位交叉核对，并打印 `ADM0_NAME`/`ADM1_NAME`。
- **教训**：涉及易混地名时，坐标验证比字符串验证可靠。

## C. 账号与环境

### C1. “认证失败”其实是工作区没绑云项目

- **现象**：资产面板报 `Request had invalid authentication credentials`；
  上传对话框报资产目录不存在；连“选择云项目”对话框本身也报同一个认证错误。
- **误导排查**：按常规刷新页面，反而把账号显示刷没、脚本仓库变成
  `No accessible repositories`。
- **根因**：Code Editor 工作区未绑定 Cloud Project，不是登录态/令牌问题。
- **解决**：右上角头像 → **Choose a Cloud Project** → 选择项目 → 确认。
- **教训**：GEE 资产类“认证错误”先查工作区项目绑定，别急着重登或刷新。

### C2. 容量限制不是代码错误

- **现象**：边界、影像数都正常，趋势统计与图表却报
  `Earth Engine capacity exceeded`。
- **根因**：一个脚本同时请求 22 年累加、231 个年份对、全省分位数、年际曲线、
  面积统计，共同上游被重复求值，超出单次运行的容量。
- **解决**：分阶段（检查 / 取数 / 导出 / 指纹 / 本地趋势），
  趋势计算整体搬到本地。
- **教训**：GEE 脚本要“一件事一次 Run”；大计算拆开比优化代码更有效。

## D. 下载与文件管理

### D1. `getDownloadURL` 的 `filename` 会被忽略

- **现象**：传了 `filename: 'Shanxi_..._2017'`，下载回来仍是 `哈希_getPixels.tiff`。
- **根因**：GEE 不接受该参数控制实际文件名。
- **解决**：下载后用“多点像元指纹”认领年份（见 D2）。
- **教训**：不要依赖下载文件名携带元数据。

### D2. 哈希文件名 + 无年份元数据 → 文件认不出年份

- **现象**：21 个哈希名文件，TIFF 标签无年份，下载时间戳挤在同一分钟。
- **解决**：8 点指纹方案——
  1. 本地在同一组像元中心取 8 个值；
  2. GEE 在**与下载文件完全一致的网格**上对每年取同样 8 点；
  3. 逐位比对，20/20 全中，并定位出漏下的 2017。
- **教训**：文件名不可控时，用“唯一指纹 + 单年份单链接”双保险。
- **详见**：独立仓库 [`yaogan-zhiwen`](https://github.com/mengzhuoer/yaogan-zhiwen)。

### D3. 同一批“年度文件”混了两个投影

- **现象**：最早的 2022 单年文件是 MODIS Sinusoidal（跟资产原生投影），
  批量 20 个是 EPSG:4326，无法叠栈。
- **根因**：下载来源不同（资产 vs 源码），默认投影不同。
- **解决**：全部按同一口径（源码计算 + EPSG:4326 + scale 500）重下 2022；
  旧文件移到 `_旧文件_勿用于分析/`。
- **教训**：批量导出必须显式固定 CRS + transform；混网格 = 返工。

### D4. 批量下载漏文件

- **现象**：预期 21 个，实收 20 个。
- **根因**：人工点链接漏了一条。
- **解决**：指纹比对发现缺 2017；单年份单链接补下；下载后再次指纹核验。
- **教训**：文件数量、年份映射、网格一致性三项都要核对。

## E. 本地代码

| 现象 | 根因 | 修复 |
|---|---|---|
| `NameError: n` | 打印/公式里变量名写错 | 统一用 `n_years` |
| `IndexError: too many indices` | 二维掩膜直接索引二维堆栈 | `complete.ravel()` 后再索引 |
| 面积文案“剔除 42%”误导 | 矩形网格含省界外角 | 改为对照官方面积，报告覆盖率 96.8% |
| 网格不一致未报错 | 只读了单文件 | 逐文件校验 `width/height/crs/transform/dtype/nodata` |

**教训**：本地脚本要在入口处“硬失败”（网格不一致直接退出），
不要靠后续结果异常来反推。

## F. 结果解读

1. **未做自相关修正**：MK 假设序列独立；自相关会让显著性偏高。
   山西案例 96.9% 显著可能被略微高估，方向与空间格局不受影响。
2. **GPP 上升 ≠ 碳汇上升**：GPP 是总光合固碳，净碳汇还要扣呼吸。
3. **边界口径**：统计基于 GAUL 山西（`Shanxi Sheng`），图上叠的是 2023 版省界；
   两者面积接近但不完全一致。正式成果若要 2023 版省界，用同一网格重跑即可。
4. **完整序列掩膜**：缺一年整像元不参与，覆盖率 96.8% 是省内有效覆盖，
   不是“剔除了 3.2% 的异常值”。
5. **趋势 ≠ 因果**：Sen + MK 只描述单调性，不解释驱动机制。

---

## G. 沉淀下来的做法

1. **分阶段**：每个 GEE 脚本只做一件事，`print` 关键诊断值，通过再进下一步。
2. **打印真实值**：名称、波段、影像数、时段数，一律打印验证。
3. **同一网格**：批量导出固定 CRS + transform；本地叠栈前逐文件校验。
4. **身份可追溯**：文件名不可控时，用多点指纹 + 单年份单链接。
5. **能力边界早识别**：GEE 容量不够就拆；本地能算的不要硬扛在云端。
6. **文档跟上现实**：方案每转向一次就更新 README，否则文档会迅速失效。
7. **算法自测**：Sen/MK/ties/分类都要有可独立运行的数值测试，
   不要只靠“图看起来对”。
